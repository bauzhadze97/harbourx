# ჯეინის საბურგერე — Telegram bot shop

Telegram-ის ბოტ-მაღაზია + ადმინ-პანელი + საჯარო ვებ-გვერდი. ერთი პროცესი,
ერთი SQLite ფაილი, build-ის გარეშე.

```
telegram-shop/
├── app/
│   ├── config.py        .env-ის წაკითხვა
│   ├── db.py            სქემა, კავშირები, ტრანზაქციები
│   ├── repo.py          ბიზნეს-ლოგიკა (ფული და მარაგი — ატომურად)
│   ├── security.py      პაროლი, სესია, CSRF, IPN-ის ხელმოწერა
│   ├── payments.py      NOWPayments-ის კლიენტი
│   ├── bot/             handler-ები, კლავიატურები, ლოკალური ემულატორი
│   ├── web/             საიტი, ადმინ-პანელი, IPN-ის endpoint
│   └── main.py          ბოტი + ვები ერთ event loop-ში
├── tests/test_shop.py   71 შემოწმება, მათ შორის კონკურენტული
├── seed_demo.py         სადემონსტრაციო მონაცემები
└── run.sh               ერთი ბრძანებით გაშვება
```

## გაშვება

```bash
cd telegram-shop
cp .env.example .env        # შეავსე BOT_TOKEN და NOWPAYMENTS_*
./run.sh
```

`run.sh` თვითონ შექმნის venv-ს და დააინსტალირებს დამოკიდებულებებს.

| რა | სად |
|---|---|
| საიტი | http://127.0.0.1:8791/ |
| ადმინ-პანელი | http://127.0.0.1:8791/admin |
| ბოტის გადახედვა | http://127.0.0.1:8791/admin/preview |
| IPN | `PUBLIC_BASE_URL` + `/ipn/nowpayments` |

სადემონსტრაციო მონაცემებისთვის: `./venv/bin/python seed_demo.py`

### ტესტები

```bash
./venv/bin/python tests/test_shop.py
```

## რა აკეთებს ბოტი

* **/start** — ფოტო + აღწერა, ორივე ადმინ-პანელიდან იცვლება, ქვემოთ ბალანსი,
  ყიდვების რაოდენობა, დაგროვებადი ფასდაკლება და რეფერალური ბმული.
* **🏢 ქალაქი** → პროდუქტი → ყიდვა. ყიდვის შემდეგ მყიდველი მაშინვე იღებს
  ადგილს და ორ ღილაკს: **🔍 ვერ ვიპოვე** (დავა) და **⭐️ შეფასების დატოვება**.
* **🖥 ბალანსის შევსება** — ვალუტის არჩევა, თანხის შეყვანა, შემდეგ
  **ერთჯერადი** მისამართი და ზუსტი რაოდენობა `<code>` ბლოკში (Telegram-ში
  შეხებით კოპირდება).
* **🎴 წესები**, **🧾 მხარდაჭერა**, **🛒 რა დევს?**, **📋 ჩემი ყიდვები**,
  **🏅 შეფასებები**, ჩატისა და არხის ბმულები.

## ერთჯერადი საფულე

ყოველ შევსებაზე `POST /v1/payment` იძახება ხელახლა და NOWPayments აბრუნებს
ახალ `pay_address`-ს **მხოლოდ იმ ინვოისისთვის**. ძველი ინვოისის მისამართი
ხელახლა არასდროს ჩნდება: ბოტი ძველ ჩანაწერს არ კითხულობს, ხოლო ბაზაში
`deposits.pay_address`-ზე უნიკალური ინდექსია, ასე რომ ერთი მისამართი ორ
შევსებაზე ვერ მოხვდება. შეზღუდვა რაოდენობაზე არ არის — მომხმარებელს ნებისმიერ
დროს შეუძლია ახალი შევსება და ახალ მისამართს მიიღებს.

## დავა და შეფასება

დავის ფანჯარა ინახება თავად შეკვეთაზე (`orders.dispute_until`), ყიდვის
მომენტში დაანგარიშებული. ნაგულისხმევი 3 საათია, იცვლება პარამეტრებში.
ვადის გასვლის შემდეგ `open_dispute` უარს ამბობს — კლიენტის მხარეს ღილაკის
დამალვას არ ვენდობით. დაკმაყოფილებისას თანხა ბრუნდება, შეკვეთა ხდება
`refunded`, ერთეული კი `withdrawn` (ხელახლა არ იყიდება).

შეფასება შეკვეთაზე ერთხელ იწერება (`reviews.order_id` — UNIQUE) და მხოლოდ
იმ ადამიანს შეუძლია, ვინც იყიდა.

## უსაფრთხოება

**ერთდროული ყიდვები.** ყველა ფულადი ოპერაცია `BEGIN IMMEDIATE`-ში სრულდება,
ანუ ჩაწერის ბლოკი მაშინვე აიღება. ერთეულის „დაკავება“ ხდება
`UPDATE … WHERE status='available'`-ით და `rowcount`-ის შემოწმებით — თუ სხვამ
დაასწრო, გაყიდვა ვარდება. ბალანსიც ასევე პირობით იცვლება. ტესტები ამას
ამოწმებს 20 პარალელური მყიდველით ერთ ცალზე და 10 პარალელური ყიდვით ისეთ
ბალანსზე, რომელიც მხოლოდ 3-ს ყოფნის.

**IPN.** ხელმოწერა მოწმდება NOWPayments-ის სქემით (გასაღებებით დალაგებული
JSON → HMAC-SHA512 → `x-nowpayments-sig`), `hmac.compare_digest`-ით. არასწორი
ხელმოწერა — 403 და არაფერი სხვა. ყოველი მიღებული body ინახება digest-ით,
ამიტომ იგივე მოვლენა მეორედ არ მუშავდება; ჩარიცხვა კი
`UPDATE … WHERE credited = 0`-ითაა დაცული, ანუ ორმაგი ჩარიცხვა შეუძლებელია
მაშინაც, როცა ორი განსხვავებული IPN ერთდროულად მოდის. ნაკლებად გადახდილ
თანხას პროპორციულად ურიცხავს.

**ადმინ-პანელი.** პაროლი scrypt-ით (n=2¹⁵), სესია HMAC-ხელმოწერილი cookie —
HttpOnly, SameSite=Strict, 8 საათი. CSRF ტოკენი სესიაზეა მიბმული და ყველა
POST-ზე მოწმდება. 8 წარუმატებელი მცდელობა → IP 15 წუთით იბლოკება. შესვლისას
hash ყოველთვის სრულდება, რომ არასწორი მომხმარებელი უფრო სწრაფი არ იყოს.
ატვირთული ფაილები სახელს კარგავს (შემთხვევითი სახელი + დაშვებული გაფართოება),
`/media/` კი ბმულს აბსოლუტურად resolve-ავს და საქაღალდის გარეთ არ უშვებს.
ყველა პასუხზე CSP, `X-Frame-Options: DENY`, `nosniff`, `Referrer-Policy`.

**ფულის აუდიტი.** `ledger` მხოლოდ დამატებადია: ყოველი მოძრაობა თავისი
ნაშთით. `admin_log` ინახავს ადმინის ქმედებებს, `ipn_events` — ყველა IPN-ს.

## ლოკალური ბოტის გადახედვა

`/admin/preview` უშვებს **ნამდვილ** handler-ებს, dispatcher-ს, FSM-ს და ბაზას,
მაგრამ Telegram-ის ნაცვლად ბრაუზერში ხატავს ჩატს. გამოსადეგია მაშინ, როცა
`api.telegram.org`-თან წვდომა არ არის, ან უბრალოდ სწრაფად უნდა შეამოწმო
ღილაკები. ყიდვა იქაც ნამდვილია — ბაზაში იწერება.

## პარამეტრები

`.env`-ში:

| ცვლადი | რისთვის |
|---|---|
| `BOT_TOKEN` | @BotFather-ის ტოკენი |
| `BOT_ADMIN_IDS` | ვის მისდის შეტყობინება ახალ დავაზე |
| `ADMIN_USERNAME` / `ADMIN_PASSWORD` | პანელის შესვლა |
| `SECRET_KEY` | 64 hex სიმბოლო; სესიების ხელმოწერა |
| `NOWPAYMENTS_API_KEY` / `NOWPAYMENTS_IPN_SECRET` | გადახდები |
| `PAYMENTS_MODE` | `auto` ან `demo` (ოფლაინ ტესტირება) |
| `PUBLIC_BASE_URL` | საიდან მოაწვდენს NOWPayments IPN-ს |
| `COOKIE_SECURE` | `1`, როცა HTTPS-ზე გაუშვებ |

დანარჩენი — ტექსტები, კონტაქტები, ფასდაკლების საფეხურები, დავის ვადა,
მინიმალური შევსება — ადმინ-პანელის **პარამეტრებში** იცვლება.

## პროდაქშენში გატანამდე

1. `SECRET_KEY` დააყენე და არ შეცვალო — თორემ სესიები ყოველ გადატვირთვაზე ჩამოვარდება.
2. `COOKIE_SECURE=1` და პანელი HTTPS-ის უკან (nginx / Caddy).
3. `PUBLIC_BASE_URL` — ნამდვილი დომენი, რომ IPN მოვიდეს.
4. `data/` და `media/` რეგულარულად დაბეკაპე; `.env` არასდროს ჩააკომიტო.
